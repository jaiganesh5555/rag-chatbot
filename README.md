# Document Chat — a RAG chatbot

A beginner-friendly chatbot built with Streamlit, LangChain, Google's Gemini API, and an in-memory vector store. Upload PDFs, UTF-8 text, or Markdown; ask questions; inspect retrieved passages and source page numbers.

## Run locally

Use Python 3.12 or 3.13. From this folder in PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
# Edit .env and set GOOGLE_API_KEY, or enter your key in the app sidebar.
.\.venv\Scripts\python -m streamlit run app.py
```

Get a key from https://aistudio.google.com/apikey. Use a free-tier project and verify your account's quota; free APIs are rate-limited, not unlimited. Defaults are `gemini-2.5-flash-lite` and `gemini-embedding-001`; model access changes, so both can be changed in the sidebar or .env.

Try `sample-documents/welcome.md` and ask “How many days of annual leave do employees receive?” Then ask “How far in advance should I request it?”

## How it works

Upload → extract text → split into overlapping passages → Gemini embeddings → in-memory vector search → send the top four passages and question to Gemini → answer with source references. Follow-up questions are rewritten using recent chat history before retrieval.

## Limits and privacy

- Maximum 10 MB per file and 200 passages per knowledge base. PDFs need a text layer; OCR is not included.
- Uploaded text is sent to Google for embeddings. Retrieved text, questions, and recent conversation are sent for answers. Google's free-tier data terms apply; use non-sensitive sample documents.
- Documents and vectors live only in the Streamlit session and disappear on restart. Changing files, embedding model, or key clears the knowledge base and chat.
- Citations are generated by the model and may be wrong; the expandable passages let you verify them. Retrieval does not guarantee that every relevant passage is found.
- This is a learning starter, without production authentication or persistent storage.
- Never commit .env, API keys, private uploads, or Streamlit secrets.

## Checks

```powershell
.\.venv\Scripts\python -m unittest discover -s tests -v
```

Offline tests cover ingestion, source metadata, vector-store integration, and limits. Live Gemini behavior requires your API key. GitHub Actions runs offline checks on every push and pull request.

## GitHub workflow

Create a public repository named `rag-chatbot` without an initial README, then run from this folder:

```powershell
git init -b main
git add .
git commit -m "Build Streamlit and LangChain RAG chatbot"
git remote add origin https://github.com/jaiganesh5555/rag-chatbot.git
git push -u origin main
```

For each finished improvement, run checks, review `git diff`, stage the intended files, commit with a clear description, and `git push`. Push tested milestones instead of automatically uploading every file save. Future improvements: streaming answers, persistent local embeddings, evaluation questions, and deployment.
